# CLI 필드북 기반 반도체 신입사원 AI 교육 확장 계획

작성일: 2026년 9월 16일  
대상: 휴대폰으로 교육에 참여하는 반도체 신입사원과 담당 강사  
상태: 추가 구현을 위한 계획안

## 1 제안 방향

기존 교육에 필드북의 설치 과정을 그대로 추가하기보다, 작업을 정의하고 결과를 검증하는 방법을 반도체 업무 사례에 적용한다. 학생은 휴대폰에서 데이터가 포함된 예시를 복사하고, AI가 만든 결과를 원문과 대조하고, 수정된 텍스트 또는 단일 HTML을 제출한다. 실제 CLI 도구 실행과 외부 서비스 연결은 강사 시연 또는 후속 PC 과정으로 제공한다.

우선 적용할 내용은 작업 계약 작성, 근거가 있는 작업지도서 검색, 두 실적표 대응 검토, 오류 재현과 회귀 검사다. 에이전트 과정은 요구사항부터 도구 계약, 실행 기록, 승인, 재시험, 인수인계까지 하나의 사례로 연결한다.

강사용 시간은 실습 난이도에 따라 산정하고 고정된 360분 문구를 사용하지 않는다. 학생 화면에는 수업 소요 시간과 카운트다운을 표시하지 않는다. 입력 기록의 업무 발생 시각은 분석에 필요한 데이터이므로 유지한다.

## 2 분석 근거와 범위

원문은 [한국AI교육진흥원 실습지원 필드북](https://kai-cli-fieldbook.pages.dev/)이다. 제공받은 접근 문구로 정상 로그인한 뒤, 공개 화면에 사용되는 교재 본문과 실습 정의를 확인했다. 접근 문구와 로그인 정보는 이 문서에 저장하지 않는다.

원문에는 다음 12개 학습 장이 있다.

1. 처음 쓰는 명령 프롬프트와 실습 폴더
2. Node.js와 npm 설치
3. Codex CLI 설치와 로그인
4. Claude Code 설치와 로그인
5. 프로젝트와 Git 및 세션 다루기
6. 작업 계약 6문장
7. AGENTS.md와 CLAUDE.md
8. 권한과 비밀정보 및 승인 경계
9. 탐색에서 검증까지 한 사이클
10. 비대화형 실행과 구조화 출력
11. 리뷰와 디버깅 및 회귀 방지
12. 배포 전 검수와 인수인계

설치 명령, 모델명, API 비용과 무료 혜택은 원문의 소개 내용으로만 확인했으며 현재 유효성을 별도로 검증한 것은 아니다. 본 계획에서는 특정 명령과 가격을 새 수업의 전제로 삼지 않는다. PC 과정에 편입할 때 공식 문서와 수업 환경에서 재확인한다.

## 4 추가 모듈 제안

시간은 강사용 준비 추정치다. 첫 수업에서 실제 완료 시간을 기록한 뒤 조정한다. 단순 복사와 응답 수신을 여러 분의 실습으로 계산하지 않고, 원문 대조와 수정·재시험을 포함한다.

| 우선순위 | 모듈 | 입력 자료 | 학생 결과물과 완료 기준 | 권장 시간 |
| --- | --- | --- | --- | --- |
| P0 | 작업 계약 작성 | 요청과 제약이 섞인 업무 의뢰 12행 | 목표·맥락·범위·제약·검증·완료 보고를 작성하고 모호한 요구 2개 질문 | 5분 |
| P0 | 근거형 작업지도서 검색 | 번호가 있는 가상 지침 16행, 질문 3개 | 답마다 조항 번호 표시; 문서에 없는 질문에는 확인 필요 표시 | 8분 |
| P0 | 두 실적표 대응 검토 | 표 A 12행, 표 B 12행 | 확정·보류·미대응 구분; 중복 별칭을 임의로 연결하지 않음 | 8분 |
| P0 | 오류 재현과 회귀 검사 | 의도적으로 틀린 HTML과 테스트 12건 | 실패 재현, 수정 요청, 동일 테스트 재실행 기록 | 12분 |
| P1 | 메시지에서 할 일 추출 | 가상 업무 메시지 12건 | 담당·기한·근거 ID 정리; 기한 없는 항목은 미정 | 5분 |
| P1 | 보고서 초안과 승인 | 설비 기록 14행과 검토 의견 | 초안→검토 반영본→승인 대기 표시; 외부 발송하지 않음 | 8분 |
| P1 | 데이터 기반 HTML 대시보드 | 소모품 이력 20행 | 원본 대조 가능한 집계·필터·결측 구분 | 15분 |
| P1 | 완료 보고와 인수인계 | 변경·시험·미확인 사항 12행 | 완료·변경·검증·제한·다음 작업을 구분한 보고 | 5분 |

추가 후보의 합계는 66분이다. 현재 모듈 은행 115분과 단순 합산하면 181분이지만, 오류 검증·HTML 제작·마무리는 기존 모듈과 중복된다. 일괄 덧붙여 교육 시간을 늘리지 않고 교체 또는 심화 선택으로 제공한다. 강사용 전체 선택은 자료 탐색용이며 전체 수강을 의미하지 않는다.

## 5 에이전트 개발 체험 설계

공통 사례는 가상 설비 기록을 읽어 이상 항목을 분류하고 인수인계 보고를 작성하는 도구다. 앞 단계에서 만든 결과물을 다음 단계 입력으로 사용한다.

| 단계 | 학습자의 행동 | 눈으로 확인할 증거 |
| --- | --- | --- |
| 요구 정의 | 12행 이상 입력을 보고 목표와 완료 조건 작성 | 무엇을 판단하고 무엇을 보류할지 명시한 작업 계약 |
| 스킬 작성 | 분류·요약 절차와 출력 규칙 정리 | 다른 입력에도 재사용할 수 있는 짧은 지침 |
| 도구 계약 | readRecords, classifyRecords, buildReport 입출력 정의 | 입력 JSON, 출력 JSON, 실패 조건 |
| 구현 | AI에 단일 HTML 생성을 요청하고 사이트에서 실행 | 함수별 시작·성공·실패, 실제 입력·출력 로그 |
| 검토와 승인 | 원문과 결과를 비교하고 승인 버튼 조작 | 승인 전에는 최종 보고가 확정되지 않음 |
| 실패 재현 | 결측·중복·문자·경계값 입력 | 오류 행이 보고에서 사라지지 않고 보류됨 |
| 수정과 회귀 검사 | 재현 절차를 전달하고 같은 시험 재실행 | 수정 전후 결과와 통과·실패 기록 |
| 인수인계 | 검증 결과와 미확인 사항을 제출 | 재현 가능한 HTML과 완료 보고 |

휴대폰에서 실행하는 HTML은 고정된 순서로 함수를 호출하는 프로토타입이다. LLM이 도구를 선택하며 동작하는 실제 에이전트와 동일하다고 설명하지 않는다. 강사는 같은 계약을 사용하는 실제 코딩 에이전트의 파일 변경·도구 실행·시험 결과를 시연하여 차이를 보여준다. 학생이 대화형 AI에 명세를 붙여넣는 것은 스킬 활용 연습이며 제품에 스킬이 설치됐다는 뜻도 아니다.

학생이 제출할 증거는 HTML, 사용한 프롬프트, 테스트 결과, 남은 제한이다. 새 API 서버를 필수로 구축할 필요는 없다. 실제 도구 선택과 외부 연결까지 확장할 경우 별도 서버, 계정, 비용, 권한 범위를 후속 과제로 정의한다.

## 6 프롬프트 제작 규격

각 예시는 다음 순서로 작성하고 한 번의 예시 복사에 전부 포함한다.

1. 업무 상황과 역할
2. 독립 실행에 필요한 가상 데이터 10행 이상
3. 분석·변환·생성할 작업
4. 출력 형식과 근거 표시 방식
5. 결측·경계값·불확실성 처리 규칙
6. 학생이 직접 확인할 완료 조건
7. 결과가 틀렸을 때 사용할 후속 수정 프롬프트

데이터 행 수에는 제목·지시문·CSV 헤더를 포함하지 않는다. 비교 과제는 양쪽 표에 각각 10행 이상을 넣는다. 파일을 받아야만 실행 가능한 예시는 기본 경로로 사용하지 않는다. 별도 실습 데이터셋 페이지의 CSV 다운로드 기능은 유지한다.

강사 정답은 학생용 복사 문자열과 분리한다. 학생에게 정답을 먼저 적어주기보다 원본 행을 대조하는 판정 규칙을 제공하고, 강사에게는 정답 ID·건수·대표 오류를 제공한다. 자유형 답변을 문자열 일치만으로 채점하지 않는다.

## 7 우선 제작할 예시 초안

### 근거형 업무 지침 요약

아래 전체 블록이 하나의 복사 대상이다. 실제 회사 절차가 아닌 교육용 가상 문서다.

```text
당신은 신입사원의 업무 문서 이해를 돕는 보조자입니다.
아래 가상 검사 자료 접수 지침만 근거로 답해주세요.

[가상 지침]
01. 접수 담당자는 자료의 접수 번호를 기록한다.
02. 모든 자료에는 작성일과 작성 부서가 있어야 한다.
03. 작성일이 없으면 보완 요청 대상으로 표시한다.
04. 작성 부서가 없으면 담당자 확인 대상으로 표시한다.
05. 파일명에 기록된 설비명과 본문의 설비명을 대조한다.
06. 두 설비명이 다르면 자동으로 고치지 않고 확인을 요청한다.
07. 측정값의 단위를 원문 그대로 기록한다.
08. 단위가 없으면 임의로 추정하지 않는다.
09. 중복 접수 번호는 별도 목록으로 분리한다.
10. 이전 버전 자료를 새 버전으로 덮어쓰지 않는다.
11. 검토 결과에는 원문 조항 번호를 남긴다.
12. 보완 요청에는 누락 항목을 구체적으로 적는다.
13. 제출자는 보완 내용을 확인한 후 수정 자료를 전달한다.
14. 담당 검토자가 확인하기 전에는 처리 완료로 표시하지 않는다.
15. 이 지침은 자료 검토 절차이며 설비 운전 기준은 포함하지 않는다.
16. 지침에 없는 질문은 담당 검토자에게 확인한다.

[과제]
1. 접수부터 완료까지의 흐름을 5문장 이내로 요약하세요.
2. '단위가 누락된 자료', '설비명이 서로 다른 자료', '중복 접수'의 처리 표를 만드세요.
3. 각 판단에 근거 조항 번호를 적으세요.
4. '자료 접수 후 설비를 재가동해도 되는가'에 문서 근거로 답하세요.
5. 자동 처리 가능한 항목과 사람 확인이 필요한 항목을 구분하세요.
문서에 없는 허용 기준이나 완료 사실을 만들지 마세요.
```

강사 확인 기준: 단위 누락은 07~08, 설비명 불일치는 05~06, 중복 접수는 09에 연결되어야 한다. 설비 재가동은 15~16에 따라 이 문서로 판단할 수 없다. 완료는 14의 확인 조건을 보존해야 한다.

후속 수정 예시: “네 답변의 각 문장을 조항과 다시 대조해줘. 문서에 없는 조치와 확정 표현을 찾아 제거하고, 바뀐 부분과 이유를 함께 보여줘.”

## 8 프로젝트 적용 순서

### 첫 번째 반영

작업 계약·근거형 검색·실적표 대응 검토의 입력 데이터와 프롬프트를 작성한다. 기존 오류 검증 모듈은 재현→수정→회귀 검사 구조로 보강한다. curriculumData.ts에 학생용 예시와 강사용 정답을 구분하여 배치하고, 기존 모듈 ID를 바꿀 때 저장된 선택과 공개 예시의 처리 방법을 함께 정한다.

### 두 번째 반영

에이전트 3개 모듈을 하나의 동일 데이터·도구 계약으로 연결한다. 강사에게 기준 HTML과 실패를 넣은 HTML을 준비하고, 학생에게는 먼저 직접 만들어볼 수 있는 생성 프롬프트를 제공한다. 생성에 실패한 학생은 기준 HTML로 검증 단계부터 계속할 수 있게 한다.

### 세 번째 반영

CurriculumManager의 선택 화면에 기본 업무형과 에이전트 개발형 조합을 제공한다. 시간은 강사용 합계만 표시한다. 예시 복사와 Firestore 공개 데이터에 입력 데이터가 누락되지 않게 한다. 수강생 화면의 프로그램 시간 표기는 추가하지 않는다.

### 네 번째 반영

폰에서 예시 복사→AI 답변→HTML 실행 또는 텍스트 제출을 시험한다. 배포된 새 버전에서 이전 기본 예시가 다시 나타나지 않는지 확인한다. 별도 브라우저로 강사 공개와 학생 수신을 검증한 뒤 배포한다.

현재 관련 파일: src/data/curriculumData.ts, src/data/upgradeCurriculum.ts, src/components/CurriculumManager.tsx, src/components/ParticipantTeamView.tsx, src/components/CodeRunner.tsx. 이 문서는 계획이며 위 기능의 신규 구현·운영 데이터 변경·배포를 수행한 결과 보고가 아니다.

## 9 수업 운영과 완료 판정

처음부터 3시간을 프롬프트 수로 채우지 않는다. 강사 설명, 학습자 입력과 검증, 생성 실패 복구, 결과 공유를 구분해 실제 진행 시간을 수집한다. 예상보다 빨리 완료하면 비교 데이터 변경, 기준 변경, 오류 주입과 재검증을 선택 과제로 진행한다.

완료 판정은 다음 증거를 기준으로 한다.

- 모든 데이터 기반 예시에 최소 10행의 입력이 포함되고 휴대폰에서 한 번에 복사된다.
- 요약과 분류의 주요 주장에 원본 행 또는 조항 근거가 있다.
- HTML은 외부 설치 없이 제공된 실행 화면에서 동작하고 390px 화면에서 조작 가능하다.
- 에이전트 프로토타입은 실제 함수 실행 기록과 승인 전후 상태를 보여준다.
- 빈 입력·경계값·형식 오류·미승인 상태 시험에서 기대 동작을 확인한다.
- 실패를 수정한 후 같은 시험을 다시 수행한 기록이 있다.
- 실제 실행하지 않은 명령이나 시험은 완료로 보고하지 않는다.
- 학생 화면에는 강의 시간과 타이머가 없고, 강사에게만 편성 시간이 보인다.
