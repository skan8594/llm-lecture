# 새 Firebase 계정으로 옮기기

현재 교안 데이터셋 11개(수율·제조 실습 포함)와 학생용 프롬프트 본문은 사이트 빌드에 정적으로 포함됩니다. CSV 복사·다운로드와 프롬프트 본문 표시는 Firebase에서 자료를 읽지 않습니다. 내용을 추가/수정할 때는 `src/data/sampleDatasets.ts`(고정 FEM 데이터는 `src/data/lithoFemCsv.ts`) 또는 `src/data/curriculumData.ts`를 변경하고 사이트를 재배포합니다. 강사용 화면에서는 CSV 미리보기·다운로드만 가능하며, 강사 브라우저의 프롬프트 초안 편집은 학생 공개본에 적용되지 않습니다.

Firestore는 차수별 수강생 제출물, 조 정보, 투표, 세션 설정과 공개 모듈 ID·완료 여부(`openModules`)에만 사용합니다. 기존 Firebase의 데이터셋 문서는 삭제하지 않았으며, 2026-10-08에 확인한 네 차수의 11개 데이터셋은 로컬 백업 `C:\Users\mokin\lecture\firebase-datasets-backup-20261008.json`에도 보관했습니다. 이 백업에는 수강생 기록이 들어 있지 않습니다.

새 계정에서 진행할 일:

1. 새 Firebase 프로젝트를 만들고 웹 앱과 Firestore 데이터베이스를 생성합니다. 기본 데이터베이스라면 별도 Database ID를 지정하지 않습니다.
2. 웹 앱 설정값(`projectId`, `appId`, `apiKey`, `authDomain` 및 필요한 경우 `firestoreDatabaseId`)을 `firebase-applet-config.json`에 반영합니다. 서비스 계정 개인 키나 계정 비밀번호는 이 저장소에 넣지 않습니다.
3. 현재는 더미 데이터 전용 공개 교육 사이트입니다. `firestore.rules`와 새 프로젝트에서 로그인 없는 읽기/쓰기가 가능하므로 실제 수강생 정보나 업무 데이터를 넣으려면 먼저 인증·권한을 도입해야 합니다.
4. `npm run lint`, `npm run test:datasets`, `npm run build:pages`를 확인한 후 `main`에 반영하면 GitHub Pages가 자동 배포됩니다.

새 프로젝트를 연결해도 기존 프로젝트의 수강생 기록은 자동으로 복사·삭제되지 않습니다. 새 계정에서 처음부터 시작하려면 이전 프로젝트는 그대로 보존하면 됩니다. 이전 기록을 옮기려면 별도 백업·이관 계획이 필요합니다.

2026-10-08 확인: `onboarding-6292d`의 기본 Firestore 데이터베이스로 웹 앱 설정을 변경했습니다. 현재 차수의 세션·조·제출물 경로 읽기와 조 경로의 임시 문서 저장/삭제가 성공했고, 검사 문서는 제거됐습니다. 이 검사는 **로그인하지 않은 클라이언트도 기록을 쓸 수 있음**을 의미합니다. 실제 수강생 정보나 업무 데이터의 운영 배포는 인증 및 보안 규칙을 정한 뒤 진행해야 합니다.

브라우저에 남은 이전 프로젝트의 수강생 캐시·투표·초안·학습 완료 상태는 새 프로젝트에서 읽지 않도록 프로젝트별 저장 키를 분리했습니다. 이전 프로젝트의 수강생 기록과 프롬프트 본문은 새 Firestore로 복사하지 않았습니다. 새 차수는 코드에 내장된 기본 모듈의 ID·완료 여부만 초기 공개하며, 강사는 모듈 선택 후 공개 상태를 다시 갱신할 수 있습니다.

배포 상태: 2026-10-08 사용자가 더미 교육 데이터의 로그인 없는 읽기·쓰기를 명시적으로 승인했으며, `onboarding-6292d`의 기본 Firestore 데이터베이스에 `firestore.rules`를 적용했습니다. `main` 브랜치에 이 변경을 반영하면 GitHub Pages 워크플로가 새 Firebase 설정과 정적 교안을 배포합니다. 이 공개 규칙은 실제 개인정보나 회사 업무 데이터에 사용하지 마세요.
